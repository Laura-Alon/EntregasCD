# Ejercicios - Tema 2: Ingeniería de Software

## Ejercicio 5 — Product Backlog con Scrum

### Tarea 1: Identifica los roles
**Product Owner (PO):** Luís. Como director de un centro educativo puede ser el Product Owner, representando los intereses de todos los stakeholders (centros educativos, profesorado). Decide qué se construye y en qué órden.
**Scrum Master (SM):** Empleado de la empresa Tech4Learning, que tenga la experiencia/conocimientos para poder hacer que el Scrum funcione correctamente y eliminar los obstáculos que impidan avanzar al equipo.
**Development Team:** Empleados de la empresa Tech4Learning.

### Tarea 4: Estima cada historia mediante la técnica de Planning Poker
*Punto de partida: Iniciar sesión en la plataforma usando un correo electrónico y contraseña — **5 puntos.***

**Historia de usuario 1:** subir material didáctico en múltiples formatos (PDF, vídeos y enlaces) → ***8 puntos.*** Mayor esfuerzo comparado con el login, pues habrá que validar los accesos (sólo los profesores asignados a esa materia/centro pueden subir el material), los tipos de documentos (PDF, vídeos, enlaces) y gestionar el almacenamiento en la plataforma (y si tiene limitaciones de tamaño)
**Historia de usuario 2:** organizar el material didáctico por temas o semanas → ***1 punto.*** El esfuerzo es menor comparado con el del login. Las funcionalidades ya están creadas, solamente es añadir etiquetas para poder filtrar el contenido.
**Historia de usuario 3:** consultar el material didáctico desde cualquier dispositivo → ***8 puntos.*** El Mayor esfuerzo comparado con el login. Debe ajustarse la interfaz de usuario para que se ajuste a los distintos dispositivos. Quizá se tenga que adaptar o modificar el diseño.
**Historia de usuario 4:** programar exámenes online con preguntas de opción múltiple y abierta → ***21 puntos.*** Es la historia que considero requiere mayor trabajo, ya que debe contemplarse las múltiples opciones de preguntas, haciendo que ambas puedan formar parte de un mismo examen sin que interfieran unas con otras. Además, de también configurar la vista para el alumno, que se guarden las respuestas seleccionadas por este y el profesor consiga ver cada respuesta identificando a cada alumno.
**Historia de usuario 5:** que los exámenes online con preguntas de opción múltiple se corrijan automáticamente → ***13 puntos.*** Compleja ya que debemos gestionar que el profesor pueda marcar las respuestas correctas cuando programa el examen sin que estas se muestren al alumno. La corrección automática puede requerir más esfuerzo si queremos que las preguntas tengan distinta puntuación (i.e. que una pregunta valga 0.5, otra 2.00 puntos...) o si el examen tiene tanto preguntas de respuesta múltiple como abierta.
**Historia de usuario 6:** recibir notificaciones de cada nueva publicación/actividad → ***5 puntos.*** El esfuerzo debería ser similar al del login.

### Tarea 5: Ordena las historias resultantes para formar el Product Backlog
1- Iniciar sesión en la plataforma usando un correo electrónico y contraseña — **5 puntos.*** → Es el punto de partida. Además, es la principal para poder acceder a la plataforma.
2 - **Historia de usuario 1:** subir material didáctico en múltiples formatos (PDF, vídeos y enlaces) → ***8 puntos.*** → Es el primer elemento que deberíamos tener en la plataforma. El material didáctico es el elemento principal de la plataforma. Sin material didáctico los alumnos no podrán acceder a la información para estudiar y poder prepararse para los exámenes.
3 - **Historia de usuario 4:** programar exámenes online con preguntas de opción múltiple y abierta → ***21 puntos.*** → Es un elemento fundamental para el PO; también es el que más puntos de esfuerzo tiene asignados. *A tener en cuenta: la velocidad de sprint del equipo. Al ser el elemento que más puntos de esfuerzo tiene, igual no sería posible hacerlo en el mismo sprint que las historias de usuario anteriores. Si fuese así, deberíamos priorizar tareas con puntos de esfuerzo menor para poder optimizar el sprint*
4 - **Historia de usuario 2:** organizar el material didáctico por temas o semanas → ***1 punto.*** → Mejora considerablemente la experiencia del usuario y tiene pocos puntos de esfuerzo.
5 - **Historia de usuario 5:** que los exámenes online con preguntas de opción múltiple se corrijan automáticamente → ***13 puntos.*** → Mejora considerablemente la experiencia. Impacto directo tanto para el profesor (que dispondrá de más tiempo para otras labores) como para el alumnado (reducción drástica del tiempo de espera para recibir la corrección y puntuación del examen). *A tener en cuenta: la velocidad de sprint del equipo, ya que es un elemento con alta puntuación de esfuerzo. Si sobrepasa la velocidad del spint, priorizar siguiente historia con menor punto de esfuerzo.*
6 - **Historia de usuario 6:** recibir notificaciones de cada nueva publicación/actividad → ***5 puntos.*** → No es imprescindible para el funcionamiento de la plataforma, pero es conveniente para que el alumno esté al día sin necesidad de consultar diariamente la plataforma.
7 - **Historia de usuario 3:** consultar el material didáctico desde cualquier dispositivo → ***8 puntos.*** → No es imprescindible para el funcionamiento de la plataforma, pero conveniente para que los usuarios puedan acceder desde un dispotivo móvil sin depender de disponer de un ordenador.
